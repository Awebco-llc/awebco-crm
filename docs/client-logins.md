# Internal Client Logins

Client Logins connects directly to the CRM. Staff sign in in the extension with their existing CRM email/password; the CRM's existing Local Listings board permissions apply. No client-portal account, pairing code, separate employee grants, or new user records are required.

The native host signs in through the existing Firebase project and keeps its refresh/ID tokens in its encrypted local vault, never Chrome storage or MCP. The CRM password is used only for sign-in. `/api/extension/config` returns the same public Firebase configuration as the CRM frontend. Staff ID tokens are verified with revocation checks for `/api/extension/listings/resources` and `/resources/:id`; these return only exact Local Listings parents/direct rows and selected company NAP. The latter is a private staff/native endpoint and includes directory credentials for encrypted local sync. The client-facing portal listing API still excludes passwords. All extension API responses are no-store; errors are fixed and request bodies/tokens/credentials are never logged.

The extension imports every directory row, including rows without credentials, and refreshes existing CRM-managed usernames/passwords and business details automatically while unlocked. Edits go to the CRM through the existing ticket link. A changed login destination needs a fresh human approval; site access and document-bound one-use fill grants are preserved. MCP only sees metadata and requests fills; it cannot sign in, unlock, reveal/export passwords, or administer accounts. Existing manually saved vault accounts are preserved.

In the CRM Local Listings board, select a client parent and choose **Export client logins**. The normal `.xlsx` file automatically includes its directory child rows and the Username/Password/Link columns, regardless of hidden board columns. Usernames and passwords are readable strings, without a passphrase or recipient software setup. String cells preserve leading zeroes/whitespace and prevent formula-looking passwords from becoming executable spreadsheet formulas. No client download is generated by an AI tool; export is a human action in the staff CRM UI.
